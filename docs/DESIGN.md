# Design decisions & trade-offs

## Retrieval
**Hybrid = dense ⊕ keyword, fused with RRF.** Dense retrieval handles paraphrase; keyword retrieval handles identifiers, acronyms and rare terms that embeddings blur. RRF (`Σ 1/(k+rank)`) needs no score calibration between cosine similarity and `ts_rank_cd`, which is why it is the default. *Trade-off:* RRF treats both rankers as equally trustworthy — with a weak embedder it can pull hybrid *below* the keyword ranker (observed in our own eval). The fix is a better embedder or a reranker, which the failure diagnosis recommends.

**Postgres for everything.** pgvector + `tsvector` in one database gives transactional ingestion, SQL filtering by document, one backup, no sync problems between a vector store and a search engine. *Trade-off:* at tens of millions of chunks a dedicated engine would scale further; HNSW + GIN comfortably serve the "hundreds of PDFs" target.

**OR-style keyword queries.** `to_tsquery('a | b | c')` over stop-word-filtered terms (tokens restricted to `[a-z0-9]+`, so no injection) keeps recall high for natural-language questions where `AND` semantics return nothing; `ts_rank_cd` ranks documents matching more terms higher.

## Chunking
**Chunks never cross page boundaries.** It costs a little context at page breaks (mitigated by sentence-aware packing and overlap) but makes every citation resolve to a real page a human can open. Verifiability was prioritised over a few points of recall.

## Agent
**Decompose → retrieve per sub-question → gap-check → reformulate.** Single-embedding retrieval of a multi-part question finds the topic but misses the facts. The gap check (best rerank score under a threshold) triggers reformulation only when needed, bounding cost with `MAX_ROUNDS`.

**Two engines behind one interface.** The heuristic engine makes the system runnable, testable and CI-gateable with zero keys; the LLM path adds fluency. Every LLM call has a fallback, and warnings are surfaced in the result rather than swallowed.

## Verification (the core idea)
An LLM judge alone can rubber-stamp. So the verifier **cross-checks the judge deterministically**:
1. the judge must return a supporting quote; the quote must appear **verbatim** (whitespace/case-normalised) in a cited passage;
2. numbers in a claim must exist in the evidence;
3. lexical coverage must clear a floor — a "supported" verdict with a fabricated quote *and* no lexical overlap is converted to **unsupported**, not just "partial" (found by a test that fed a scripted hallucinating judge).
Strict mode removes unsupported claims from the report but lists them with reasons — transparency over silent filtering. The agent **abstains** (no sections, a stated gap) when evidence is absent, and abstention is measured.

## Evaluation
**Gold labels are `(file, page, passage)`, not chunk IDs**, so golden sets survive re-chunking, new embedders and re-ingestion. A hit matches if file, page and passage coverage line up; credit is given once per gold passage so overlapping chunks cannot inflate nDCG.
**Synthetic cases are leaky by construction** (questions reuse the passage's own words) — documented as a smoke test; hand-written paraphrase cases carry the real signal.
**Diagnosis, not just scores:** each failure is labelled (`ranking`, `lexical_gap`, `semantic_gap`, `fusion_gap`, `chunk_boundary`, `corpus_gap`, plus answer-level labels) by comparing per-mode ranks, and mapped to a concrete configuration change.

## Feedback loop
Expansions are learned from failures, but (a) start as `proposed` and require human approval, (b) are learned only from a deterministic **train** half, and the API refuses to learn from a `test` run, so the before/after delta is measured on cases the learner never saw. In our tiny demo the held-out delta was zero — reported as such. The machinery matters more than the demo number.

## Operations
**Pure-ASGI middleware** (not `BaseHTTPMiddleware`) so SSE streaming is never buffered. CORS is outermost so 401/429 responses carry CORS headers (otherwise browsers hide the real error).
**Signed URLs** solve "iframes can't send auth headers" without putting the API key in a URL; a token is bound to one document and expires in 5 minutes.
**Migrations:** autogenerated from the models, run at startup under `pg_advisory_xact_lock` (safe with multiple workers); databases created by `create_all` in earlier versions are detected and stamped at the baseline, then upgraded — verified with data preserved.
**Known limits:** rate limiter is per-process; ingestion uses background tasks (no retry queue); no per-user ACLs.
